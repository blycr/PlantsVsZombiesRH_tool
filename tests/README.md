# Trainer verification

在 Windows x64 和 .NET SDK 10 下，使用当前适配的融合版 4.0.5 `GameAssembly.dll` 执行下方命令。验证器只修改自己的临时内存，不会启动或附加游戏。它覆盖两个 C# 实现的七项功能、同时开启、重复开关、原始字节还原和倍速恢复；实际关卡效果仍需要单独测试。

On Windows x64 with .NET 10 and the supported PVZ Fusion 4.0.5 game files:

```powershell
dotnet run --project tests/TrainerVerification.csproj -- ./GameAssembly.dll
```

The runner verifies the build fingerprint, loads a disposable copy of the game's PE sections into its own process, and exercises all seven Console and GUI patch implementations through real Windows memory APIs. It checks instruction boundaries, original bytes, simultaneous enable, cave reuse, restoration, and a recorded timeScale reset. Unity's timeScale setter is replaced in the disposable copy with a recording stub. It never attaches to a running game. Passing an optional second path exports generated hook code for disassembly or emulation.

This verifies patch mechanics; gameplay effects and level transitions still require an in-game check. Game binaries are not included in the repository.

To export generated hook bytes for external disassembly or emulation:

```powershell
dotnet run --project tests/TrainerVerification.csproj -- ./GameAssembly.dll ./hooks.json
```

The JSON contains test-process addresses and generated bytes. It is a verification output and should stay out of source control. For build and runtime requirements, see [BUILDING.md](../BUILDING.md).
